## 1. QEvict：面向长上下文解码的可恢复量化 KV 淘汰机制

**来源**：arXiv cs.LG  
**链接**：https://arxiv.org/abs/2608.05326  
**标签**：KV-Cache · 长上下文 · 量化 · 推理优化

自回归大模型推理越来越受 KV-Cache 内存占用的制约。主流做法基于注意力分数淘汰'不重要'的 token，但这种策略隐含了不可逆决策——一旦淘汰便无法恢复。QEvict 提出可恢复的量化 KV 淘汰方案，在减少内存footprint的同时保持对注意力漂移的鲁棒性，使长上下文解码在有限显存下仍能维持质量。

**核心要点**：
- 指出现有 KV 淘汰策略的不可逆缺陷：丢弃的 token 无法在后续步骤中挽回
- 结合量化与可恢复淘汰，在内存压缩与生成质量间取得平衡
- 针对长上下文场景，降低注意力漂移带来的质量退化

## 2. WitCert：面向 KV-Cache 量化的可证明运行时风险可观测与门控

**来源**：arXiv cs.AR  
**链接**：https://arxiv.org/abs/2607.28699  
**标签**：KV-Cache量化 · 运行时监控 · 风险门控

当前 KV-Cache 量化仅通过离线基准均值验证，部署系统无法判断当前请求是否正被压缩损害。WitCert 提供了一个可证明'可靠'的运行时度量器——被称为'KV 量化的 DTrace'：为每一层、每个头、每一步给出精确注意力与压缩注意力之间总变差的上界，从而在请求级别实现实时风险观测与门控。

**核心要点**：
- 提出逐层/逐头/逐步的压缩误差上界，提供可证明的运行时风险度量
- 类比 DTrace，将离线验证升级为在线可观测性
- 支持在服务质量受损前触发门控（如回退到高精度）

## 3. PLoRA：基于近数据处理（NDP）的池化内存系统，实现高性价比多 LoRA 服务

**来源**：arXiv cs.AR  
**链接**：https://arxiv.org/abs/2608.05483  
**标签**：多LoRA · 推理服务 · NDP · 内存池化

多 LoRA 服务让一个基座模型衍生出上千个专用变体（每用户/任务/智能体一个适配器），部署常需持有 1000+ 适配器。其难点在于工作负载与 GPU 供给倒置——TB 级内存 vs 仅数十 TFLOPS，且现有系统都从 CPU 内存逐级搬运适配器。PLoRA 提出 NDP 增强的池化内存系统，将计算推近数据以降低搬运开销。

**核心要点**：
- 揭示多 LoRA 服务的核心矛盾：海量适配器内存 vs 有限算力
- 引入近数据处理（NDP）减少适配器在层级内存间的搬运
- 面向 1000+ 适配器规模的成本优化

## 4. EdgeXpert：面向内存高效 LLM 推理的边端设备，结合 MoE 与投机解码

**来源**：arXiv cs.AR  
**链接**：https://arxiv.org/abs/2608.05303  
**标签**：边端推理 · MoE · 投机解码 · 内存访问优化

LLM 在设备端部署对个性化边缘应用日益关键，主要瓶颈是 FFN 层中的外部内存访问（EMA）。投机解码与混合专家（MoE）是有前景的解法：投机解码通过一次生成多个 token 候选减少解码阶段数；MoE 稀疏激活降低单次计算量。EdgeXpert 将二者协同设计于边端硬件以压缩 EMA。

**核心要点**：
- 定位边端 LLM 推理瓶颈为 FFN 的外部内存访问（EMA）
- 协同投机解码（减少解码步数）与 MoE（稀疏激活）
- 面向资源受限设备的端侧推理加速

## 5. RIG-RoPE：关系与实例门控的旋转位置编码，含时长感知时间坐标

**来源**：arXiv cs.CL  
**链接**：https://arxiv.org/abs/2608.05154  
**标签**：RoPE · 位置编码 · 多模态 · 时间建模

旋转位置编码（RoPE）是现代语言模型的核心组件，并已通过 M-RoPE 等多维变体扩展到多模态 LLM（将位置通道拆分为时间/高度/宽度子空间）。本报告指出静态多维位置分配的两处局限，提出 RIG-RoPE：以关系与实例门控动态调整位置，并引入时长感知的时间坐标。

**核心要点**：
- 剖析 M-RoPE 等静态多维位置分配的局限性
- 以关系/实例门控实现动态、内容感知的位置编码
- 时长感知时间坐标改善视频/时序多模态建模

## 7. OBASE：基于对象地址空间工程改善内存分层

**来源**：arXiv cs.OS  
**链接**：https://arxiv.org/abs/2603.00378  
**标签**：内存分层 · 地址空间 · 操作系统 · DRAM优化

硬件与 OS 的内存分层机制已广泛部署，但数据中心仍过度配置 DRAM。根本原因是热度碎片化：分配器按大小而非访问模式放置对象，导致热/冷对象交错于同一页，单个热对象使整页被标记为活跃，拖累周围冷对象。OBASE 以对象为粒度重建地址空间以提升分层效率。

**核心要点**：
- 指出内存分层失效的根因：按大小分配导致热度碎片化
- 以对象为粒度（而非页）重组地址空间
- 降低数据中心 DRAM 过度配置，提升分层命中率
