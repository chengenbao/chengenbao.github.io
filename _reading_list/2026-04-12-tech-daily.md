### 1. 投机解码回到训练侧：TorchSpec 的规模化实践

**来源：** [PyTorch Blog](https://pytorch.org/blog/torchspec-speculative-decoding-training-at-scale/)　**标签：** `投机解码 · 训练系统 · MFU`

**要点：** TorchSpec 把推测执行引入训练循环：小模型先猜下一段 token 的前向激活，大模型并行验证，猜对则跳过部分计算，猜错则丢弃重算。与数据并行的通信窗口重叠后，在超大规模集群上实测端到端 MFU 提升。文章给出失败重算的显存预算与稳定性分析。

**点评：** 推理侧技术反向输入训练侧，是 2026 年初训练系统最有意思的转向。当集群规模受制于互连带宽而非算力时，"用计算填通信"是必然的工程选择。

### 2. LLM 生成 CUDA 内核：KernelBench 协议下的真实水位

**来源：** [Stanford Scaling Intelligence](https://scalingintelligence.stanford.edu/pubs/kernelbench.pdf)　**标签：** `GPU内核 · AI生成代码 · 基准`

**要点：** 对照阅读 KernelBench 论文与代码库：250 个真实 PyTorch 算子任务上，前沿模型一次生成的内核正确率较高，但"同时跑赢专家手写基线"的比例仍集中在简单算子。评估协议（正确性 + 加速比双门槛）已成为后续工作的事实标准。

**点评：** 内核生成的 SOTA 迁移曲线值得持续跟踪——从"能编译"到"能跑对"用了不到一年，从"能跑对"到"能跑赢"正在发生。性能工程的人力结构会随之改变。

### 3. GGML 加入 HuggingFace：量化推理生态的整合信号

**来源：** [HuggingFace Blog](https://huggingface.co/blog/ggml-joins-hf)　**标签：** `量化 · GGML · 边缘推理`

**要点：** GGML 团队加入 HuggingFace，llama.cpp 系生态与 HF Hub 的模型分发、量化格式（GGUF）与 Transformers 的互操作将更深整合。对终端用户的意义：从云端到笔记本的同一条模型资产管线，量化格式转换的摩擦显著下降。

**点评：** 边缘推理的竞争焦点正在从"单机能不能跑"转向"模型资产管理 + 量化自动调优"。GGML 的 C/C++ 内核积累与 HF 的分发网络互补性极强。

### 4. 大模型 GPU 训练原理的万字长读（系统知识梳理）

**来源：** [腾讯技术工程 / KM](https://km.woa.com/articles/show/632641)　**标签：** `GPU训练 · 系统基础 · 教程`

**要点：** 从张量并行的数学原理到 NVLink/InfiniBand 拓扑的工程约束，系统梳理大模型 GPU 训练的完整知识栈：矩阵乘的通信量分析、ZeRO 分级的显存账本、流水线并行的气泡公式。适合作为新同学的系统入门与老同学的查漏手册。

**点评：** 3D 并行（DP/TP/PP）的"通信量-显存-气泡"三角权衡是所有训练系统的第一性原理。市面上讲解这组权衡的中文长文不多，值得收藏。

### 5. 推理服务的小算子优化：MLA 与 KV 缓存的协同

**来源：** [arXiv cs.LG](https://arxiv.org/abs/2604.07808)　**标签：** `MLA · KV缓存 · 推理优化`

**要点：** 多头潜在注意力（MLA）通过低秩压缩 KV 缓存大幅降低显存占用，但其吸收（absorb）计算把矩阵乘搬进了注意力内核内部，给张量核的利用带来新挑战。该工作给出 MLA 专用内核的分块策略与流水线排布，在 DeepSeek 系架构上进一步提升吞吐。

**点评：** 模型架构的每一次"省显存"创新，都会催生一轮内核重构。MLA 内核优化是当前 vLLM/SGLang 竞争的技术制高点之一。

### 6. 通用 Agent 技能化：CUDA 优化作为可复用技能

**来源：** [HuggingFace Blog](https://huggingface.co/blog/custom-cuda-kernels-agent-skills)　**标签：** `AI Agent · CUDA · 工程实践`

**要点：** 续读 HF 的 Agent skill 实践：把编译-运行-性能分析做成标准化反馈接口后，同一个 Agent 骨架可以迁移到 Triton 内核、SIMD 汇编等不同目标平台。"技能"的抽象让优化能力像库一样被复用和版本化。

**点评：** 当"优化某类内核"变成一个可安装、可审计的技能包，性能知识的传承方式将从师徒制变成工程化分发。这是 AI 对系统工程的深层改变。
