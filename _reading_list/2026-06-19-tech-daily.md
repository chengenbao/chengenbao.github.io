## 1. CODEBLOCK：以正确粒度监督代码大模型训练

**来源**：arXiv cs.LG  
**链接**：https://arxiv.org/abs/2606.18286  
**标签**：代码LLM · SFT优化 · 损失函数 · 代码粒度 · 训练效率

代码大模型的监督微调通常对所有 token 施加均匀的交叉熵损失，隐含地假设每个 token 的学习信号价值相同。CODEBLOCK 指出，将自然语言中的 token 级别掩码直接迁移到代码上会破坏语法和语义上连贯的程序单元，因为代码依赖结构化的块级依赖（函数、循环、条件分支）。该工作提出块粒度监督机制，在保留代码语义完整性的同时，聚焦高价值代码块的学习信号，提升代码 LLM 的 SFT 效果。

**核心要点**：
- 均匀 token 损失忽略了代码的结构化语义单元特性
- 块级粒度监督比 token 级掩码更适合代码场景
- 方法对函数、循环、条件分支等语法单元保持完整性
- 可直接用于现有代码 LLM 的 SFT 流程改进

## 2. DRIFT：基于 On-Policy 数据归因的指令数据精炼

**来源**：arXiv cs.LG  
**链接**：https://arxiv.org/abs/2606.18307  
**标签**：SFT · 数据筛选 · 数据归因 · On-Policy · LLM训练

优化 SFT 的训练数据分布是提升 LLM 能力上限的关键挑战。现有数据筛选方法善于在预算受限时加速训练，但难以突破能力上限。DRIFT 的核心思路是：不再寻找「保住性能的小子集」，而是将数据分布向「最能提升模型能力的样本」方向精炼。通过 On-Policy 数据归因，DRIFT 识别对当前模型最有价值的训练实例，动态调整数据分布以持续推动能力边界。

**核心要点**：
- 区分「压缩训练预算」与「提升能力上限」两种不同的数据优化目标
- On-Policy 归因基于模型当前状态评估样本价值，优于静态筛选
- 数据分布精炼而非数据剔除，保留更多有效学习信号
- 适用于大规模 SFT 数据集的质量提升

## 3. SAE 干预不可靠：被压制行为的干预后恢复现象

**来源**：arXiv cs.LG  
**链接**：https://arxiv.org/abs/2606.18322  
**标签**：稀疏自编码器 · 可解释性 · 安全干预 · LLM安全 · 特征抑制

稀疏自编码器（SAE）将残差流激活分解为可解释特征，被广泛用于大模型安全防御：通过钳制特定"有害特征"来阻止模型输出危险内容。然而本文发现一个被忽视的故障模式：即便成功抑制了目标 SAE 特征，被压制的有害行为仍可能在干预后恢复。这意味着基于 SAE 特征钳制的安全防御可能存在系统性的可绕过性，对依赖 SAE 进行安全监控的系统提出严峻警告。

**核心要点**：
- SAE 特征钳制看似成功，但有害行为可通过替代路径恢复
- 现有基于 SAE 的安全防御机制存在可靠性缺陷
- 干预后恢复现象揭示模型内部表示的冗余性
- 对可解释性驱动的安全方法提出新的研究挑战

## 4. LiveStack：集群级全栈实时仿真的 OS 支持

**来源**：arXiv cs.OS  
**链接**：https://arxiv.org/abs/2606.18958  
**标签**：操作系统 · 全栈仿真 · 分布式系统 · 硬件评估 · 集群仿真

在部署前对分布式软件栈和新兴硬件组件进行评估，需要集群级全栈仿真。理想的仿真须同时满足：全栈保真度（运行未修改的生产栈）和仿真性能（支持迭代配置探索）。现有方法无法兼顾两者。LiveStack 提出一种基于 OS 层面的集群级全栈仿真方法，通过操作系统原语实现对未修改生产软件栈的高保真模拟，同时维持足够的仿真吞吐量，为大型分布式 AI 训练集群的硬件/软件协同设计评估提供新手段。

**核心要点**：
- 解决全栈保真度与仿真性能不可兼得的核心矛盾
- 基于 OS 层面而非 hypervisor 层面，避免修改生产软件栈
- 支持集群规模的分布式软件栈评估
- 对新兴硬件（如 AI 加速器）的预部署验证具有重要价值

## 5. CHERI-D：面向时间内存安全的高效内联对象 ID 架构

**来源**：arXiv cs.AR  
**链接**：https://arxiv.org/abs/2606.19055  
**标签**：硬件安全 · CHERI · 时间内存安全 · 体系结构 · 内存保护

CHERI 是目前领先的硬件/软件协同系统，提供原生空间安全保障，但其对时间内存安全的支持依赖软件层面方案，效率有限。CHERI-D 提出通过内联对象 ID 机制，在 CHERI 体系结构中原生支持高效的时间内存安全，填补了 CHERI 的架构空白。时间内存安全（如 use-after-free 防护）是现代编程语言和操作系统的核心安全需求，CHERI-D 的硬件级支持可大幅降低其运行时开销。

**核心要点**：
- CHERI 现有架构仅提供空间安全，时间安全依赖软件代价昂贵
- CHERI-D 通过内联对象 ID 将时间安全检查硬件化
- 防止 use-after-free 类漏洞，无需大幅牺牲性能
- 对 Rust/C++ 安全语义的硬件加速具有参考价值

- LoRA 并非在所有场景都是最优选择

- DoRA、LoRA+ 等变体在特定条件下可超越原始 LoRA
- 提供可直接参考的方法选型实验对比
