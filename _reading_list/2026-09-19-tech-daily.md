## 1. SiliconBench：统一内存桌面端 LLM 服务的速度、显存与保真度评测

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2609.19169
**标签**：LLM推理 · Apple Silicon · 服务评测 · 显存管理 · Agent

在统一内存桌面端并发部署本地 LLM，既要留出内存余量又要保证输出保真度，而单纯比拼速度的榜单常常忽略这两点。论文提出 SiliconBench，从速度、内存、保真度三个维度对 9 款 Apple Silicon 推理引擎进行评测，覆盖 Qwen3、Qwen3.5、Gemma 4 的对话与 Agent 场景，并用分类任务对照 NVIDIA 参考机检测质量回退。研究给出三条解读准则：服务架构成熟度、内存纪律、多节点扩展能力。

**核心要点**：
- 三视角评测框架：将速度、内存占用、输出保真度并列，纠正唯吞吐论的偏误
- 实测发现显式内存预算并不等于留有内存余量，部分栈在并发下仍会挤占资源
- 提供以 DGX Spark 为补充的跨平台性能参照，便于桌面与数据中心横向对比

## 2. MeshKV：面向可扩展 Transformer 解码加速器的片上网络 KV Cache 架构

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2609.19207
**标签**：KV Cache · NoC · 推理加速 · FPGA · 长上下文

自回归 Transformer 解码受限于瓦片化加速器上不规则的 KV Cache 搬运，既有压缩与 DRAM 放置方案仍把流量压在集中式内存通路上，成为长上下文服务的瓶颈。论文提出 MeshKV，用轻量级片上网络把 KV 块以分组流方式传输，协同设计亲和条带化、带去重抑制的多播以及掩盖预取/计算/softmax 的流水线。在 8x8 FPGA 上以 LLaMA-2-7B、Mistral-7B 跑 8K-32K 上下文，互联流量最多降 58%，KV 带宽利用率提升 2.1 倍，多流吞吐最高 1.9 倍。

**核心要点**：
- 把 KV Cache 当作分组流在 NoC 上搬运，化解集中式内存路径的热点瓶颈
- TaKV 亲和条带化分散 home 节点、Mare 多播去重，降低热点负载
- Pad 机制让预取、瓦片乘、流式 softmax 在信用对齐 FIFO 后重叠执行

**核心要点**：
- 把模型按层分段，以由易到难的课程序列驱动师生知识迁移
- 理论分析累积误差，证明逐层课程能加速收敛并稳定迁移

## 4. Stiefel 注意力：投影矩阵几何如何主导优化器选择

**来源**：cs.LG
**链接**：https://arxiv.org/abs/2609.19363
**标签**：注意力机制 · Riemannian优化 · Stiefel流形 · 权重衰减 · 理论

注意力中的查询/键投影 W_Q、W_K 几乎总用欧氏优化器训练且无几何约束。论文将其约束到 Stiefel 流形上，并用携带每帧一个标量二阶矩、以信任域限步、极坐标回缩的黎曼 Adam 进行优化。四条命题在 float64 下数值验证该更新在嵌入度量下是最速下降、与梯度尺度无关、良态且 O(d) 等变；第五条揭示权重衰减在 Stiefel 流形上的黎曼梯度恒为零，因此注意力几何能在模型其余部分被衰减驱动的坍缩周期中幸存。在模算术 grokking 任务上，单次运行即达 97.0% 验证准确率。

**核心要点**：
- 将 Q/K 投影约束到 Stiefel 流形，给出黎曼 Adam 的严格收敛性质
- 证明权重衰减在流形上梯度恒为零，注意力几何对坍缩免疫
- 小任务上单次训练即达 97% 准确率，凸显几何约束的价值

## 5. 低方差奖励下组相对优化的优势尺度校准失衡：诊断与有界恢复

**来源**：cs.CL
**链接**：https://arxiv.org/abs/2609.19164
**标签**：RLVR · GRPO · 优势函数 · 奖励校准 · 对齐

在验证器式 RLVR 中，组相对优化常把优势尺度当作实现细节。论文区分两类低方差情形：不应成为偏好信号的亚分辨率抖动，以及可信但很小的基数差距（应在不扭曲 KL 校准的前提下学习）。据此提出优势尺度三路校准接口，同一组内尺度分母同时决定奖励分支强度、提示级批次权重，以及奖励分支还原到原始基数尺度时诱导的有效 KL 校准。该接口解释了 RLOO 让可信小差距被 KL 主导、而 GRPO 标准差分母会无界放大微小差距的原因，并进一步给出 Reward-Resolution Protocol 与 MaxNorm-AC。

**核心要点**：
- 区分亚分辨率抖动与可信小差距，避免把噪声误当偏好信号
- 三路校准接口统一控制奖励强度、批次权重与 KL 校准
- 解释 RLOO/GRPO 在低方差奖励下的尺度行为差异，并给出修复协议

## 6. Async GRPO with LoRA：用存储桶、代理与无 NCCL 的跨 HF Jobs 训练

**来源**：HuggingFace
**链接**：https://huggingface.co/blog/asyncgrpo-lora-hfjobs
**标签**：GRPO · LoRA · 异步训练 · 分布式 · 强化学习

Hugging Face 工程博客介绍了一套跨多个 HF Jobs 运行异步 GRPO + LoRA 的实用方案：用一个共享存储桶（bucket）做样本与权重的交换中枢，以一个轻量代理（proxy）协调 rollout 与训练，全程不依赖 NCCL 集合通信。这种做法把生成与更新解耦，绕开了传统同构多卡训练对高速互联的强依赖，适合在弹性、异构的云作业间扩展强化学习训练。

**核心要点**：
- 用存储桶而非 NCCL 在多作业间交换样本与权重，降低互联门槛
- 轻量代理解耦 rollout 与训练，实现真正的异步 GRPO
- LoRA 增量使得权重同步开销极小，便于弹性扩展
