## 1. MiMo-V2.5 全链路推理优化：把混合 SWA 效率推向极限

**标签**：LLM推理 · KVCache · 混合滑动窗口注意力 · MoE · 推理加速

本文面向 MiMo-V2.5 模型族（融合混合滑动窗口注意力 Hybrid SWA、稀疏 MoE 与多模态编码器）提出了一套全链路推理优化方案。理论上 Hybrid SWA 可显著降低注意力计算量与 KVCache 占用，但要在生产环境中真正落地需要大量工程打磨。作者系统性地重构了 KVCache 管理系统，并针对 SWA 与 MoE 的协同瓶颈做了精细化调度，把理想收益转化为可量化的线上吞吐与显存提升。

**核心要点**：
- Hybrid SWA 相比 Full Attention 可同时压缩注意力算力和 KVCache 存储，但工程实现门槛高
- 针对 MoE 与多模态编码器的混合负载设计了专门的 KVCache 与调度优化
- 给出从算法到系统层的全链路优化范式，对同类长上下文/稀疏模型部署有参考价值

## 2. ShortOPD：用短到长在线策略蒸馏修复被剪枝的 LLM

**来源**：arXiv cs.LG
**链接**：https://arxiv.org/abs/2607.13124
**标签**：结构化剪枝 · LLM压缩 · 知识蒸馏 · 自由生成 · 模型恢复

结构化剪枝是硬件友好的 LLM 压缩手段，但以往多在选择题任务上验证，压缩后的检查点在真实自由生成场景会崩溃。本文指出关键现象：压缩后贪心 pass@1 几乎归零，但 pass@k 在重采样下大幅恢复——说明有用生成只是被"降级"而非消失。为此提出 ShortOPD，用短序列到长序列的在线策略蒸馏（on-policy distillation）重建被压缩模型在开放式生成上的能力。

**核心要点**：
- 揭示剪枝模型在选择题与自由生成上表现脱节的归因：有用样本被降级而非彻底丢失
- 提出 Short-to-Long 在线策略蒸馏，先在短输出上对齐再迁移到长生成
- 让结构化剪枝后的 LLM 在部署真正需要的生成任务上恢复可用性

## 3. 重新审视 Muon 优化器：矩阵分解视角下的优势来源

**来源**：arXiv cs.LG
**链接**：https://arxiv.org/abs/2607.13246
**标签**：优化器 · Muon · 大模型训练 · 矩阵分解 · 理论分析

Muon 近期作为强优化器在大模型训练中崭露头角，它通过近似正交化重塑梯度更新，被报道优于 Adam/AdamW。大量理论工作将其解释为谱范数下的梯度下降。然而哪些优势真正来自更新规则本身、哪些来自其他实现细节仍不清晰。本文从矩阵分解角度重新评估 Muon，厘清其有效性的真实来源，为优化器设计提供更扎实的理论依据。

**核心要点**：
- Muon 通过近似正交化梯度更新，在 LLM 训练中表现优于 AdamW
- 现有理论多将其归因为谱范数下的 steepest descent，但证据并不充分
- 从矩阵分解视角拆解 Muon 优势来源，区分更新规则与工程实现的影响

**来源**：PyTorch Blog

PyTorch-Triton 3.7 版本引入了 Triton Plugin Extensions 系统，提供了一套框架，可把自定义编译器 Pass、方言（含其算子）以及 DSL 扩展动态加载进上游 Triton。这意味着内核与编译优化的开发者无需 fork 整个 Triton 即可注入自己的转换逻辑，大幅降低了 Triton 后端的定制与实验门槛，对 GPU 内核性能调优和领域专用编译流程都有直接价值。

**核心要点**：
- Triton 3.7 新增 Plugin Extensions，支持运行时动态加载自定义编译器 Pass
- 可注入自定义方言（dialect）、算子与 DSL 扩展，无需 fork 上游 Triton
- 降低了 GPU 内核与编译优化定制的门槛，便于领域专用编译流程实验

## 5. AI 解码芯片的经济学：重平衡算力、容量与带宽

**链接**：https://arxiv.org/abs/2607.13068
**标签**：推理芯片 · GPU架构 · 显存带宽 · 算力利用率 · LLM解码

主流 GPU 普遍"重算力、轻容量"：配置了海量浮点吞吐却只配了很少内存来装下现代模型。而 LLM 解码阶段几乎不需要算力、却需要大量内存——解码时 GPU 浮点单元利用率仅个位数百分比，所需内存又只能与多余算力捆绑购买。本文从经济学视角剖析这一错配，探讨如何重新平衡算力、容量与带宽，以更高性价比支撑高效 LLM 推理。

**核心要点**：
- 主流 GPU 算力过剩而显存不足，与 LLM 解码阶段"低算力、高内存"的需求错配
- 解码时浮点单元利用率仅个位数百分比，算力被严重浪费
- 提出从成本结构重平衡算力/容量/带宽，指导更高效的推理芯片设计

## 6. CIMERA：面向 LLM 推理的可重构精度存算一体架构

**来源**：arXiv cs.AR
**链接**：https://arxiv.org/abs/2607.13649
**标签**：存算一体 · 可重构精度 · LLM推理 · 低精度 · 能效

LLM 带来巨大的算力与内存压力，权重量化精度在准确率、吞吐与能耗之间扮演关键角色，而现代 LLM 负载呈现明显的异构性与精度容忍度，更适合自适应精度执行。本文提出 CIMERA——一种在互联与内存中计算（Compute-in-Interconnect and Memory）、支持可重构精度的架构，针对从数据中心到功耗受限边缘设备的 LLM 推理场景，在能效与精度间做动态权衡。

**核心要点**：
- LLM 负载对权重精度有强异构容忍度，适合自适应精度执行
- CIMERA 将计算下沉到互联与内存（CIM），降低数据搬运开销
- 支持可重构精度，在准确率、吞吐与能耗间动态平衡，覆盖云到边缘

## 7. TuxBot：基于 LLM 的语义感知在线操作系统调优

**来源**：arXiv cs.OS
**链接**：https://arxiv.org/abs/2605.15026
**标签**：OS调优 · 大模型 · 内核参数 · 在线优化 · 语义感知

在线 OS 调优能改善长运行服务，但现有控制器把调度、功耗、内存、I/O 旋钮当成黑盒变量、仅优化标量奖励，既忽略旋钮间的策略结构，又会在应用指标缺失时失效，还可能把运行中的服务推入持久退化的坏配置。本文提出 TuxBot，一个主机侧、语义感知的在线 OS 调优系统，利用 LLM 理解旋钮间的结构化关系，更稳健地适配真实在线主机。

**核心要点**：
- 传统 OS 调优把各旋钮当黑盒、只优化标量奖励，易陷入持久退化区
- TuxBot 用 LLM 理解调度/功耗/内存/I/O 旋钮间的策略结构
- 语义感知使其在应用指标缺失时仍能稳健适配在线真实主机
