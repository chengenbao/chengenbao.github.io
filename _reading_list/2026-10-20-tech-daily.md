## 1. 内存带宽才是瓶颈：边缘 GPU 上查询式分割解码器的剖析与加速

**来源**：arXiv cs.AR
**链接**：https://arxiv.org/abs/2610.22377
**标签**：边缘GPU · 内存带宽 · 推理剖析 · Roofline · 分割模型

查询式分割模型在工作站 GPU 上可实时推理，但在边缘设备上，其 Transformer 解码器严重受限于内存带宽——这一瓶颈在标准 FLOP 分析中不可见，并随输入分辨率和 DRAM 带宽受限而加剧。论文用 FP16 Roofline 分析（启用张量核 GEMM 并读取硬件 DRAM 计数器）揭示：非张量核聚合算子才是真正的瓶颈。

**核心要点**：
- 标准 FLOP 分析会掩盖真实瓶颈，边缘端解码器实际是内存带宽受限而非算力受限
- 通过硬件 DRAM 计数器的 FP16 Roofline 定位出非张量核聚合算子为关键开销来源
- 工作分辨率和 DRAM 带宽越受限，瓶颈越严重，对边缘部署调度有直接指导价值

## 2. MemLLM：端侧 RAG 的存内加速与预计算 KV Cache 方案

**来源**：arXiv cs.AR
**链接**：https://arxiv.org/abs/2610.22579
**标签**：存内计算 · RAG · KV Cache · 端侧推理 · I/O墙

端侧检索增强生成（RAG）能在保护隐私的同时实现个性化 LLM 推理，但其长度不对称性使 prefill 成为主导瓶颈。离线预计算 KV Cache 可缓解服务端 prefill 开销，但多 GB 缓存经窄互连传输在端侧形成严重 I/O 墙。MemLLM 提出端到端存内加速架构来化解这一问题。

**核心要点**：
- RAG 的长度不对称性使 prefill 成为端侧推理的主要瓶颈
- 预计算 KV Cache 在多 GB 规模下遭遇窄互连带来的严重 I/O 墙
- 存内加速（In-Storage Acceleration）路径可绕过互连瓶颈，值得关注

## 3. BS-Spec：基于 BFP 位共享的自推测解码与 LUT 混精加速

**来源**：arXiv cs.AR
**链接**：https://arxiv.org/abs/2610.22877
**标签**：推测解码 · 混合精度 · BFP · LUT · LLM推理

推测解码可提升推理吞吐，但传统方案需要独立 draft 模型与额外 KV Cache，现有自推测方法又存在工作负载不敏感的 draft 配置和低效混精执行问题。BS-Spec 提出基于 BFP 的位共享自推测解码，配合 LUT 驱动的混合精度加速，覆盖从大 batch 到长上下文的多样服务场景。

**核心要点**：
- 传统推测解码需独立 draft 模型与额外 KV Cache，开销大
- 自推测方法的 draft 配置通常对工作负载不敏感，导致效率损失
- BFP 位共享 + LUT 混精可在不牺牲质量的前提下提升执行效率

## 5. TileDRAM：面向 3D DRAM GPGPU 的编译器可控 Tile 布局

**来源**：arXiv cs.AR
**链接**：https://arxiv.org/abs/2610.23767
**标签**：3D DRAM · GPGPU · 编译器 · 内存布局 · 行缓冲冲突

现代 GPU 编译器为张量到线程和片上资源的映射提供了丰富的布局抽象，但 CU-local 的 3D DRAM 架构缺少描述 operand-tile 如何在 DRAM 地址空间排布的对应抽象。缺少该抽象会使结构化 tile 访问遭遇严重的行缓冲冲突。TileDRAM 为此提出编译器可控的 tile-to-DRAM 布局机制。

**核心要点**：
- GPU 编译器缺乏对 3D DRAM 地址空间内 tile 排布的抽象
- 传统地址映射会让结构化 tile 访问遭遇严重行缓冲冲突
- 编译器可控的 tile-to-DRAM 布局可系统性缓解该冲突
