## 1. Kara：基于滑动窗口 KV Cache 压缩的高效推理 LLM 服务

**来源**：arXiv cs.CL  
**链接**：https://arxiv.org/abs/2607.01237  
**标签**：KV Cache 压缩 · LLM 推理 · 链式思维 · 吞吐量优化 · 滑动窗口

推理型大语言模型生成的长链式思维（CoT）会积累海量 KV Cache，导致解码延迟高、吞吐量受限。Kara 方案识别了现有 KV Cache 压缩技术的两大瓶颈：静态压缩策略无法适应推理过程中动态变化的注意力模式，以及压缩后精度损失难以恢复。论文提出基于滑动窗口的自适应 KV Cache 压缩框架，在保证输出质量的前提下大幅降低内存占用和推理延迟。

**核心要点**：
- 识别现有 KV Cache 压缩方案在推理 LLM 场景下的两大关键局限性
- 提出滑动窗口自适应压缩策略，动态追踪注意力权重分布变化
- 在降低 KV Cache 内存的同时保持推理质量，提升整体服务吞吐量
- 针对长 CoT 场景进行专项优化，适配推理密集型任务

- 支持跨硬件平台（不同 GPU 型号）的推理性能快速评估
- 覆盖预填充（prefill）和解码（decode）阶段的端到端仿真

## 5. MxGLUT：面向混合精度 GEMM 的可重构 LUT 中心广播数据流加速器

**来源**：arXiv cs.AR

**标签**：LLM 推理加速 · 查找表 · 混合精度 · GEMM · 硬件设计

LLM 推理中权重量化（FP8 激活 + 低比特整型权重）导致注意力与 GEMM 之间存在混合精度不统一问题，现有 LUT 加速器仅针对 FP8-INT4 场景且需要独立的浮点数据通路。MxGLUT 提出以 LUT 为中心的可重构广播数据流架构，统一处理混合精度 GEMM 操作，消除冗余硬件模块，在多种量化格式下实现高效推理加速。

**核心要点**：
- 以可重构查找表（LUT）为核心，统一支持多种混合精度格式的 GEMM
- 广播数据流设计显著减少数据搬运开销，提升硬件利用率
- 消除独立浮点数据通路，简化硬件架构并降低面积功耗
- 覆盖 prefill 和 decode 两阶段，适应 LLM 全推理流程

## 6. 3DLS：面向分解式 LLM 服务的 3D 逻辑堆叠架构

**来源**：arXiv cs.AR  
**链接**：https://arxiv.org/abs/2607.01617  
**标签**：LLM 服务 · 3D 芯片堆叠 · PD 分离 · 张量并行 · 互联架构

LLM 服务中预填充-解码（PD）分离与张量并行（TP）的结合面临 Die-to-Die 互联争用问题：KV Cache 传输与 TP 集合通信共享同一带宽，增加解码关键路径延迟。3DLS 提出 3D 逻辑堆叠芯片架构，通过垂直方向的高带宽 Die-to-Die 通道将 KV Cache 传输与 TP 通信物理隔离，消除混合流量争用。

**核心要点**：
- 利用 3D 逻辑堆叠在垂直方向提供专用高带宽通道
- 物理隔离 PD 分离的 KV Cache 传输流量与 TP 集合通信流量
- 消除解码关键路径上的互联争用，降低端到端延迟
- 为超大模型长上下文服务场景提供可扩展的硬件架构方案
