## 1. 预条件空间取整：重新设计 4-bit AdamW 优化器状态量化

**来源**：arXiv/cs.LG
**链接**：https://arxiv.org/abs/2610.12444v1
**标签**：4-bit量化 · AdamW · 优化器状态 · 预条件 · 训练效率

量化 AdamW 的优化器状态可显著降低持久化存储与显存占用，但量化误差会沿动量递推传播并扰动后续自适应更新。本文从「取整空间」（量化器在相邻重构级别间选择的坐标）重新设计 4-bit 优化器状态量化：针对二阶矩在零点邻域的量化单元做局部分析，发现「小的状态均值误差」并不等价于「下一步小的预条件误差」。据此提出新的取整策略，在保持训练稳定的同时大幅降低量化带来的优化偏差。

**核心要点**：
- 量化误差沿 AdamW 动量递推传播，直接扰动自适应学习率更新
- 局部二次型构造证明：二阶矩的小均值误差 ≠ 下一步小预条件误差
- 以「取整空间」视角重构 4-bit 量化，降低优化偏差且不改训练流程
- 保持收敛性的同时显著压缩优化器状态存储

## 2. GPU 统一虚拟内存的实用化：Ember 让离散显存 GPU 也能超订阅

**来源**：arXiv/cs.OS
**链接**：https://arxiv.org/abs/2610.13408v1
**标签**：GPU · 统一虚拟内存 · 显存超订阅 · UVM · 内存管理

随着 GPU 工作集超出显存容量，应用必须超订阅显存、只保留热数据在 GPU 上。NVIDIA 统一虚拟内存（UVM）支持超订阅，但一旦数据超过 GPU 显存，其故障驱动的数据放置会浪费互联带宽并造成 GPU 利用率不足。Ember 在不依赖放置提示、性能剖析或应用改造的前提下，让 UVM 超订阅在现货 GPU 上变得实用，既利用 GPU 显存速度又最小化互联带宽浪费。

**核心要点**：
- GPU 工作集超出显存，UVM 超订阅是当前主流方案但性能随溢出急剧退化
- UVM 故障驱动放置浪费 PCIe/NVLink 带宽、GPU 空闲等待数据迁移
- Ember 无放置提示 / 无剖析 / 无改码，使 UVM 超订阅在现货 GPU 实用化
- 兼顾 GPU 显存带宽与最小化跨设备传输开销

## 3. VFold：对称感知的跨层 Value Cache 压缩

**来源**：arXiv/cs.CL
**链接**：https://arxiv.org/abs/2610.12338v1
**标签**：KV Cache · 跨层压缩 · 长上下文 · 推理显存 · 对称感知

KV Cache 在长上下文解码中占据大量显存，利用跨层相似性的压缩方案多数需要改动模型结构并带来可观开销。VFold 提出对称感知的 value cache 合并策略，在减少缓存显存的同时避免有害的性能退化与解码期架构开销，且可与其他压缩手段协同使用。

**核心要点**：
- 长上下文下 KV Cache 显存占用成为主要瓶颈
- 现有跨层压缩多需改架构、带来解码开销
- VFold 用对称感知合并压缩 value cache，无架构改动、无解码开销
- 可叠加既有压缩方法进一步降本

## 4. SparseDecoding：解码感知剪枝，让 LLM 推理更准更快

**来源**：arXiv/cs.CL
**链接**：https://arxiv.org/abs/2610.12327v1
**标签**：LLM推理 · 结构化剪枝 · Hessian · 解码感知 · 显存带宽

LLM 解码阶段受内存带宽限制，基于 Hessian 的免训练分层剪枝是主流解法，但这类方法用自然序列算 Hessian，而解码时模型喂的是自生成 token，两者存在分布偏移。SparseDecoding 提出「解码感知」剪枝，按实际解码分布计算重要性，在同等稀疏度下显著降低精度损失与延迟。

**核心要点**：
- 解码阶段内存带宽受限，剪枝减少读参即可降延迟
- 传统 Hessian 剪枝用自然文本，与自回归解码分布偏移
- SparseDecoding 按解码分布重算 token 重要性，更贴合真实推理
- 同等稀疏度下精度更高、推理更快

## 5. UMA 架构下 CPU-GPU 内存共享的系统刻画

**核心要点**：
- UMA 共享内存常因不透明导致低效拷贝或错误直访
- 在数据面传输与控制面协调两个维度系统刻画正确性与性能
- 在四类平台上得出四条指导结论
- 开源可移植库 libumsh，跨平台保证正确与高效共享

## 6. DynaTE：动态 Token 执行加速扩散式 LLM

**来源**：arXiv/cs.AR
**链接**：https://arxiv.org/abs/2610.11284v1
**标签**：扩散LLM · 动态Token执行 · 并行细化 · 推理加速 · dLLM

扩散式 LLM（dLLM）以双向并行细化缓解自回归顺序解码瓶颈，但其并行迭代细化与离散 token 生成既不匹配 AR 加速器也不匹配 DiT 加速器。DynaTE 提出动态 Token 执行，按需分配计算、减少跨去噪迭代的冗余，提升 dLLM 推理吞吐。

**核心要点**：
- dLLM 双向并行细化突破 AR 顺序解码瓶颈，但加速硬件适配难
- 现有 dLLM 加速器减少词表处理与冗余迭代计算
- DynaTE 动态决定每步执行哪些 token，削减冗余计算
- 在不改模型的前提下提升扩散 LLM 推理吞吐
