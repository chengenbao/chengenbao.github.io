- 无需微调目标模型，可直接接入现有 LLM 推理栈

## 2. Cache-Resident LLM 推理：利用 GB 级末级缓存消除内存带宽瓶颈

**来源**：cs.AR  
**链接**：https://arxiv.org/abs/2606.25353  
**标签**：LLM推理 · 缓存架构 · 内存带宽 · 硬件加速

LLM 推理性能的主要瓶颈在于内存层级间的数据搬运。本文探索了在 GB 级末级缓存（LLC）中常驻 LLM 权重与 KV 缓存的新型架构方案，借助大容量片上 SRAM 实现了比传统 HBM 方案高出数量级的内存带宽与访问延迟，为下一代 AI 推理芯片设计提供了重要参考。

**核心要点**：
- 分析了 LLM 推理中内存带宽瓶颈的根本原因及其随模型规模的恶化趋势
- 提出 Cache-Resident 推理架构，将模型权重和 KV-Cache 置于 GB 级 LLC 中
- 与 HBM 方案相比，带宽提升数量级，推理延迟显著降低

## 3. TokenSpeed-Kernel：面向多芯片 LLM 推理的可移植高性能内核

**来源**：PyTorch  
**链接**：https://pytorch.org/blog/lightseek-tokenspeed-kernel/  
**标签**：LLM推理 · 多硬件后端 · CUDA内核 · 可移植性

TokenSpeed-kernel 是一个独立开源的 LLM 推理内核子系统，旨在解决多硬件后端带来的复杂性问题。它通过分层可移植 API 设计和高性能内核实现，统一了 NVIDIA、AMD、Intel 等不同硬件上的 LLM 推理后端，使开发者无需为每套硬件重写内核代码。

**核心要点**：
- 提出分层可移植 API 设计，将推理逻辑与硬件后端彻底解耦
- 实现了覆盖 NVIDIA/AMD/Intel 等主流 AI 芯片的统一高性能内核
- 作为独立开源子系统发布，可轻松集成到现有 PyTorch 推理流水线

- 动态调整推理策略（批大小、量化精度、层卸载），实现延迟-能耗 Pareto 最优
- 在主流移动平台上验证，平均节能 30%+ 且推理质量无明显下降
