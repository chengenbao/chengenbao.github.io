## 1. PATTON：让商用 PIM 承载生产级 LLM 服务

**来源**：arXiv (cs.AR)  
**链接**：https://arxiv.org/abs/2609.11392  
**标签**：PIM · LLM推理 · KV缓存 · 显存管理 · 能效

PATTON 提出一套 PIM 运行时，将生产级 LLM 服务引擎（动态分配/共享/回收逻辑 KV 块）与商用存内计算（Processing-in-Memory）硬件对接。它针对 Value 缓存中 GEMV 效率、单 token 写入效率与容量之间的根本冲突，设计了分层粒度分配与 Commit Zone 暂存机制。在不修改 PIM 处理单元的前提下，相比基线平均加速 1.95×、能效提升 4.83×，并保持与 vLLM 原生 GPU KV 缓存相当的命中率。

**核心要点**：
- 逻辑 KV 块与物理 PIM 粒度的一对一映射，固化物理布局并简化命令生成
- Commit Zone 暂存部分 Value 块，实现高效的单 token 写入后再提交到 GEMV 优化布局
- 跨注意力执行与运行时触发的 prefill 重算，平均 1.95× 加速、4.83× 更高能效

## 2. REACH：面向 HBM AI 推理的控制器级长跨度 ECC

**来源**：arXiv (cs.AR)  
**链接**：https://arxiv.org/abs/2609.10861  
**标签**：HBM · ECC · 内存可靠性 · 微架构 · 推理

REACH 针对高带宽内存（HBM）成本高企、需更强纠错能力的场景，提出控制器微架构，用长跨度纠错码在相近码率下提供更强的保护，同时避免直接在 HBM 带宽上做代价高昂的解码。它利用读主导的 LLM decode（顺序读可聚合并行、稀疏写限制校验更新），以内码纠正常见错误、外码仅用于已知擦除修复。在最高错误压力下 Ramulator2 仍可维持 1.88 TB/s 应用吞吐，相比直接长跨度方案节省 55.8% 控制器面积与 57.7% 功耗。

**核心要点**：
- 读主导的 LLM decode 提供有利场景：顺序读支持跨度聚合、稀疏写限制校验流量
- 差分校验绑定写流量，协同端点设计保留 32B 事务而无需额外数据突发
- 在解析目标下控制器面积减少 55.8%、建模功耗降低 57.7%

## 4. Entwine：协调 GPU 瓦片计算与细粒度通信以最小化完成时间

**来源**：arXiv (cs.AR)  
**链接**：https://arxiv.org/abs/2609.11562  
**标签**：GPU · 通信重叠 · 张量并行 · 调度 · SM资源

Entwine 针对高性能 GPU 计算将张量切分为瓦片以复用数据与并行，但单瓦片提前完成会创造计算-通信重叠机会、而两者进度不匹配又会限制收益的问题，提出协调瓦片计算顺序、细粒度通信与 SM 资源分配的调度方法。它在代表性张量并行 LLM 负载上相比 cuBLAS+NCCL 几何平均加速 1.232×（最高 1.433×），并优于最优重叠基线 3.1–9.8%。

**核心要点**：
- 重排瓦片计算顺序，使数据以更均匀的节奏产出供通信消费
- 配合基于 SM 的细粒度通信内核，以低延迟、低开销处理瓦片结果
- 协调 SM 资源在通信与计算间的分配，平衡通信推进与计算减速

## 5. K/V 缓存干预：解耦表征对齐与人格表达

**来源**：arXiv (cs.CL)  
**链接**：https://arxiv.org/abs/2609.11020  
**标签**：KV缓存 · 表征干预 · 大模型推理 · 人格控制 · 解码器

本文研究解码器-only 语言模型中的 K/V 缓存干预——将目标条件化的 K/V 轨迹移植进源人格生成——作为人格控制的结构化干预面。在 Llama-3.1-8B 上对固定源-目标人格对施加 13 种干预配置，发现表征级对齐（V-gap 高）并不等价于行为级人格表达；仅中间层（9–20 层）替换能在保留词法多样性的同时产生显著目标标记表达，且位置扰动会一致抑制目标人格表达。

**核心要点**：
- 所有层带 K/V 替换均获强局部 V 空间对齐，但仅中间层兼顾目标表达与词法多样性
- 全层与中层替换对齐度相近（0.94 vs 0.89）却呈现不同词法多样性剖面（TTR 0.65 vs 0.77）
- 位置扰动（滞后/打乱）统一抑制人格表达，表明表征相似度不足以预测下游行为

## 6. AgentZip：面向 AI Agent 沙箱的首个内存压缩系统

**来源**：arXiv (cs.OS)  
**链接**：https://arxiv.org/abs/2609.11294  
**标签**：OS · 内存压缩 · Agent沙箱 · 高扇出 · 推理

高扇出 Agent 负载中单个任务会派生大量并发沙箱会话，且这些沙箱源于同一模板、执行相关轨迹，存在显著的内存冗余。AgentZip 是首个专为 AI Agent 沙箱设计的内存压缩系统，利用模板相对与跨沙箱冗余，将压缩范围扩展到任意有收益表示的页面，并将开销控制从压缩时页面选择转移到恢复时预取，同时把昂贵压缩对齐到 LLM 等待期。相比 Linux 配置，沙箱自有内存最高减少 8.7×（Linux 为 2.1×），并将激进压缩的减速从 3.1× 降至 1.40×。

**核心要点**：
- 同时利用模板相对与跨沙箱冗余，压缩非完全相同的沙箱页面
- 将开销控制从压缩时保守选页转为恢复时预取，并据 Agent 执行阶段对齐压缩
- 沙箱内存最高降 8.7×，恢复预取与执行感知调度将减速从 3.1× 降至 1.40×
