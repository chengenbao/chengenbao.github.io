## 1. 剖析 Nvidia Hopper 上 LLM 推理的 GPU 利用率

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2609.12923
**标签**：GPU利用率 · Hopper · 推理优化 · SM · decode

论文指出单个 SM 利用率百分比会让 LLM 推理负载看起来计算饱和，却掩盖了实际有效工作量，问题不在于计数器错误，而在于它把多种不同机制压缩成了一个数字。在 decode 阶段该问题最严重——每个请求只产生一个新 token，且密度低。文章拆解了利用率指标背后的不同机制，帮助工程师区分“忙”与“有效忙”，从而更精准地定位推理瓶颈。

**核心要点**：
- 单一 SM 利用率指标合并了多种机制，易误判计算饱和
- decode 阶段单请求单 token、密度低，利用率失真最严重
- 区分“忙”与“有效忙”是定位推理瓶颈的关键

## 2. 面向 PyTorch 的硬件属性算子性能剖析（Operator Profiler）

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2609.11938
**标签**：PyTorch · 性能剖析 · 硬件计数器 · 算子归因 · GPU

框架级 profiler 只暴露算子耗时、缺少硬件计数器，而 GPU profiler 只给硬件计数器、缺算子归属，手动关联两者既易错又不可扩展。作者提出 Operator Profiler 硬件归因流水线，通过三种互补方式自动将硬件指标（如 cache / 内存带宽 / 计算吞吐）关联到 PyTorch 算子，实现可扩展的性能根因分析。

**核心要点**：
- 框架 profiler 与 GPU profiler 各自存在归因盲区
- 自动将硬件指标关联到 PyTorch 算子，避免手工映射
- 三种互补归因方式，支持大规模可扩展剖析

## 3. Vortex：打通极限压缩与高效 LLM 推理

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2609.12208
**标签**：LLM压缩 · 向量量化 · 稀疏 · 推理加速 · 加速器

向量量化（VQ）与输入相关稀疏等极限压缩能显著降低大模型显存占用，但难点在于把这些压缩真正转化为推理效率。在传统脉动阵列加速器上，VQ 的反量化开销极高，反而拖慢推理。Vortex 针对这一矛盾设计软硬件协同方案，将极限压缩的显存收益落地为实际推理加速。

**核心要点**：
- VQ/稀疏压缩显存收益大，但传统加速器反量化开销高
- 极限压缩到推理效率之间存在落地鸿沟
- 软硬件协同设计是把压缩收益转化为加速的关键

## 4. 跨 HF Jobs 的异步 GRPO + LoRA：一个桶、一个代理、无需 NCCL

**来源**：HuggingFace
**链接**：https://huggingface.co/blog/asyncgrpo-lora-hfjobs
**标签**：GRPO · LoRA · 分布式训练 · 强化学习 · HuggingFace

Hugging Face 技术博客介绍了一套去中心化的异步 GRPO 训练方案：利用 HF Jobs 与 Storage Buckets 作为共享存储，通过一个代理（proxy）在多个独立作业间交换 LoRA 权重与梯度，完全绕开了 NCCL 这类紧耦合通信后端。该架构让训练任务可以弹性跨作业调度，提升资源利用率与容错性。

**核心要点**：
- 用 Storage Bucket + proxy 替代 NCCL 做权重/梯度交换
- 多独立 Job 异步执行 GRPO，资源调度更弹性
- 解耦通信后端，提升训练容错与可扩展性

## 5. AKTS：面向语言模型智能体的亚微秒级内核策略切换

**来源**：cs.OS
**链接**：https://arxiv.org/abs/2609.12276
**标签**：操作系统 · 内核调度 · LLM智能体 · QoS · 策略切换

GPU 支撑的 LLM 服务常在同一批 CPU 上复用交互请求与后台批处理。请求突发时需保护首 token 时延（TTFT），突发间隙则需让后台任务推进——固定内核策略只能顾一头。AKTS 提出亚微秒级内核策略切换机制，使 agentic OS 控制能在不同负载形态下动态切换调度策略，同时兼顾两类目标。

**核心要点**：
- 交互请求突发期需保 TTFT，间隙期需推进后台任务
- 固定内核策略无法同时兼顾两类目标
- 亚微秒级策略切换实现动态、低开销的调度适配

## 6. SeqMoE：基于预测与图兼容的 MoE 卸载以逼近满载性能

**来源**：cs.OS
**链接**：https://arxiv.org/abs/2609.12978
**标签**：MoE · 显存卸载 · 专家并行 · 调度预测 · 推理性能

MoE 在结构上天然适合卸载：只需少量激活专家驻留设备显存，若能及时加载，理论上可逼近“全量权重驻留显存”的满载性能。SeqMoE 提出预测式与图兼容的 MoE 卸载策略，解决专家激活顺序与加载时序的错配问题，把 MoE 的结构优势真正转化为接近满载的推理吞吐。

**核心要点**：
- MoE 仅激活少量专家，结构天然适合显存卸载
- 难点在于专家激活与加载时序错配
- 预测+图兼容卸载可逼近全量驻留的满载性能
