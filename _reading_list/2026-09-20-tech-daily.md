## 1. MeshKV：面向可扩展 Transformer 解码加速器的片上网络 KV Cache 互连架构

**来源**：arXiv (cs.AR)
**链接**：http://arxiv.org/abs/2609.19207v1
**标签**：KV Cache · NoC · Transformer 解码 · 加速器 · 长上下文

自回归 Transformer 解码受限于平铺加速器上不规则的 KV Cache 搬移，既有压缩与 DRAM 放置方案仍把流量集中在中心化内存路径上，成为长上下文服务的瓶颈。MeshKV 提出一种 KV Cache fabric，将块以分组流的形式在轻量级片上网络（NoC）上传输，通过 TaKV 仿射条带化打散 home 位置降低热点、Mare 多播配合可验证去重抑制，以及 Pad 填充等协同设计，缓解长上下文下的内存墙问题。

**核心要点**：
- 将 KV Cache 块封装为分组流在 NoC 上传输，打破集中式内存路径的流量热点
- TaKV 仿射条带化（affine striping）分散 home 节点，均衡片上负载
- Mare 多播 + 可验证重复抑制，降低多播冗余带宽开销
- 面向长上下文解码场景，提升平铺式加速器 KV Cache 移动的可扩展性

## 2. MiX：面向端到端低比特视觉-语言模型加速的微缩放反转技术

**来源**：arXiv (cs.AR)
**链接**：http://arxiv.org/abs/2609.19683v1
**标签**：低比特量化 · VLM · 边缘推理 · Microscaling · 内存带宽

在边缘设备部署视觉-语言模型（VLM）受内存带宽严重制约，往往需要 sub-8-bit 的激进量化；但多模态 token 间极大的动态范围差异会让标准块格式出现“微缩放崩溃”——单个巨大离群值劫持共享指数，使周围元素下溢。MiX 提出 Micro-Inverted-Scaling，对离群值路径与常规路径分别缩放，在严格的面积/功耗约束下端到端量化 VLM，恢复被崩溃压制的精度。

**核心要点**：
- 揭示标准 microscaling 块格式在多模态 token 上的“离群值劫持”崩溃现象
- 对离群值通道与常规通道采用反转式独立缩放，避免共享指数下溢
- 面向边缘加速器面积/功耗硬约束，实现端到端 sub-8-bit VLM 量化
- 缓解内存带宽瓶颈，直接提升边缘端 VLM 推理吞吐

## 3. 量化固定微架构 MXFP4 加速器上硬件构造语言（HCL）的影响

**来源**：arXiv (cs.AR)
**链接**：http://arxiv.org/abs/2609.18792v1
**标签**：MXFP4 · HCL · RTL · 硬件设计 · QoR

硬件构造语言（HCL）承诺提升硬件设计效率并自动生成 RTL，但既有对比多为定性、或在不同设计上比较 QoR，难以分离“语言效应”与“设计效应”。本文在相同的固定设计（OCP MXFP4 块点积量化算子）上横向对比主流 HCL，量化其在同一微架构下生成电路的质量差异，为 HCL 选型提供可比基准。

**核心要点**：
- 以同一固定微架构（MXFP4 块点积）隔离语言本身带来的差异
- 系统性量化主流 HCL 生成 RTL 的 QoR（面积/时序/功耗）
- 区分“语言效应”与“设计效应”，填补 HCL 对比的方法论空白
- 为量化加速器 RTL 生成工具链选型提供实证依据

## 4. 面向现代 GPU ISA 压缩的自动化指令编码合成

**来源**：arXiv (cs.AR)
**链接**：http://arxiv.org/abs/2609.18662v1
**标签**：GPU · 指令集 · ISA 压缩 · 编码合成 · 指令供给

现代 GPU kernel 越来越挤压指令供给路径（instruction supply path），而固定指令容器会留下大量布局空隙。本文提出一种自动化编码合成框架，将指令布局建模为在已校验指令格式字段规范上的受限槽位分配问题，把语义字段身份与物理比特位置解耦，并支持 tied/pinned/free 放置约束，适用于需要反复重排编码以压缩指令体积的 GPU ISA。

**核心要点**：
- 将指令编码布局形式化为带约束的槽位分配问题
- 解耦“语义字段身份”与“物理比特位置”，便于重排压缩
- 支持 tied/pinned/free 多种放置约束，适应复杂 GPU 指令格式
- 缓解 GPU kernel 的指令供给瓶颈，缩小指令容器体积

## 5. Netkit：为容器网络专门定制的 Linux 数据包投递路径

**来源**：arXiv (cs.OS)
**链接**：http://arxiv.org/abs/2609.18633v1
**标签**：Linux · 容器网络 · 网络命名空间 · 数据包投递 · 云原生

云原生微服务依赖网络命名空间做隔离，容器间通信开销仍是关键性能瓶颈；同主机共置虽缓解部分开销，却无法匹配单一网络命名空间内的通信性能。Netkit 通过专门化 Linux 数据包投递路径，在不改写应用、且完整支持容器化应用所期望的完整 Linux 网络栈的前提下，消除容器跨命名空间通信的额外开销。

**核心要点**：
- 定位容器跨网络命名空间通信的冗余开销根因
- 专门化 Linux 数据包投递路径，无需应用改写
- 保留容器化应用依赖的完整 Linux 网络栈语义
- 在云原生微服务场景下显著提升同主机容器通信性能

## 6. TyPatch：将历史补丁转化为 Typestate 规则用于内核 Bug 检测

**来源**：arXiv (cs.OS)
**链接**：http://arxiv.org/abs/2609.13728v1
**标签**：Linux 内核 · Bug 检测 · 静态分析 · LLM · Typestate

历史 Linux 内核补丁蕴含可复用于原修复点之外缺陷知识。已有工作用 LLM 从补丁生成静态分析检查器来发掘新内核 Bug，但完整检查器生成要求模型既还原补丁表达的缺陷语义、又实现对象跟踪、别名分析、路径状态维护等复杂程序分析机制。TyPatch 将补丁转化为 typestate 规则，降低对复杂分析机制的依赖，提升 LLM 生成检查器的可行性与检出率。

**核心要点**：
- 复用历史内核补丁中沉淀的缺陷知识，跨修复点发现新 Bug
- 用 LLM 将补丁转化为 typestate 规则，避免手写复杂分析器
- 降低对对象跟踪/别名分析/路径状态维护的建模负担
- 提升基于 LLM 的内核静态检查器生成的可行性与覆盖

## 7. dQwen3.5：基于混合注意力（Attention+RNN）骨干的扩散语言模型

**来源**：arXiv (cs.LG)
**链接**：http://arxiv.org/abs/2609.20751v1
**标签**：扩散语言模型 · 混合架构 · RNN · 自回归适配 · Qwen

从预训练自回归（AR）模型改造出 diffusion language model（DLM）是一条低成本路线；但几乎所有改造都从 full-attention Transformer 起步，而 AR 建模已转向交错 attention 与 RNN 层的混合架构。RNN 结构上是因果的、难以双向化，给改造带来障碍。本文探究这类混合骨干能否通过适配成为有效的 DLM，并给出相应的训练与双向化方案。

**核心要点**：
- 提出从混合 attention+RNN 骨干（而非 full-attention）改造 DLM 的方法
- 解决 RNN 因果结构难以双向化的核心障碍
- 相比从零训练或 full-attention 改造，复用 AR 预训练权重更省成本
- 为扩散语言模型的骨干架构选择提供新实证
