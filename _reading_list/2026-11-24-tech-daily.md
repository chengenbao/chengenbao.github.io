## 1. BitPrefill：W1.58A4 张量核加速计算受限型 LLM Prefill

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2611.26657
**标签**：LLM推理 · 低比特量化 · Tensor-Core · Prefill加速 · 硬件加速

低比特量化能显著降低 LLM 推理成本，但以往方案多针对显存受限的解码阶段优化，对计算受限的 prefill 阶段关注不足。BitPrefill 提出 W1.58A4（1.58 位权重 + 4 位激活）配置，并设计了可充分利用 GPU 张量核（Tensor-Core）的矩阵乘内核，使 prefill 阶段在计算受限场景下获得接近峰值的加速。该工作为低比特 LLM 在 prefill 瓶颈上的落地提供了实用的硬件协同设计路径。

**核心要点**：
- 针对计算受限的 prefill 阶段而非显存受限的解码阶段进行低比特优化
- W1.58A4 配置（1.58 位权重 + 4 位激活）兼顾精度与压缩比
- 设计充分利用 GPU 张量核的矩阵乘内核，逼近计算峰值

**核心要点**：
- RL 后训练生成的 rollout 轨迹此前多被直接丢弃
- 将教师 RL 轨迹转化为蒸馏监督信号，复用降低训练成本
- 在保持下游表现的同时显著减少 PPO/GRPO 类训练开销

## 3. Cruella：面向 LLM 推理的统一微缩放与浮点点积单元

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2611.27323
**标签**：LLM推理 · 微缩放格式 · 浮点点积 · 加速器设计 · 数值格式

加速器在制造时即固定了原生支持的数值格式，而 LLM 推理对不同层与算子的数值精度需求各异。Cruella 提出一种统一支持微缩放（microscaling, MX）与浮点点积的计算单元，让同一硬件既能高效执行 MX 量化又能处理传统浮点，避免为单一格式定制造成的利用率浪费。该设计在 LLM 推理的精度-效率权衡上提供了更灵活的硬件基础。

**核心要点**：
- 加速器原生数值格式固化，难以适配 LLM 多变精度需求
- 统一支持微缩放（MX）与浮点点积的单点积单元设计
- 同一硬件灵活兼顾 MX 量化与传统浮点，提升利用率

## 4. FOREST：协调树状 HBF、RRAM 与 HBM 的高效投机解码

**来源**：cs.AR
**链接**：https://arxiv.org/abs/2611.27701
**标签**：投机解码 · 近存计算 · RRAM/HBM · LLM加速 · 存储层次

投机解码通过轻量草稿模型加速 LLM 生成，但受限于内存带宽与草稿质量。FOREST 提出一种协调树状基于哈希的 Bloom filter（HBF）、RRAM 与 HBM 的存储层次方案，将草稿候选以近存方式高效存储与检索，缓解 HBM 带宽压力并提升草稿命中率。实验表明该协同设计在投机解码吞吐与能效上均有明显收益。

**核心要点**：
- 投机解码受 HBM 带宽与草稿质量双重瓶颈制约
- 用树状 HBF + RRAM 近存存储草稿候选，缓解带宽压力
- 存储层次协同设计提升草稿命中率与整体能效

**核心要点**：
- Agent 重复发送增长的历史上下文导致资源线性膨胀
- 运行时上下文淘汰在保正确前提下裁剪可丢弃历史
- 显著提升高并发 Agent 服务的吞吐与资源利用率

- 边云协同需要可移植的负载迁移能力
- 自托管 WebAssembly 运行时实现运行时中立的 C/R
- 异构边云节点间轻量、可移植的暂停与恢复

## 7. LEAN：基于库的异步联邦微调框架

**链接**：https://arxiv.org/abs/2611.26805
**标签**：联邦学习 · LoRA微调 · 异步聚合 · 分布式训练 · 隐私计算

基于低秩适配器（LoRA）的联邦微调通常用平均聚合来合并各设备更新，但设备异构与异步导致收敛与效率问题。LEAN 提出基于库的异步联邦微调方法，将 LoRA 更新组织为可异步合并的库，并设计适配的聚合策略，在保护数据隐私的同时提升联邦场景下基础模型微调的可扩展性与收敛质量。

**核心要点**：

- 将 LoRA 更新组织为可异步合并的库
- 在隐私保护下提升联邦微调的可扩展性与收敛质量
